## Bugs found and fixed (same commit)

1. **`doctor --remote` false FAIL** when the key is in the unit's
   `EnvironmentFile`. Doctor now reads the service environment names
   (systemd `Environment` / `EnvironmentFiles`, Windows service registry
   `Environment`) and gives a WARN: a rotation then needs a restart.
   `apikey list` shows `source=service-env`; `apikey rotate` refuses.
2. **Bridge: HTTP 400 with go-sdk v1.7.0 clients.** The client sends
   `server/discover` with the protocol version in `_meta`; the server wants it
   in `Mcp-Protocol-Version`, and from protocol 2026-07-28 also wants
   `Mcp-Method` / `Mcp-Name`. The bridge now sets these headers. Test:
   `TestBridgeGoSDKClientNoErrors`.
3. **Tier-0 tools audited remote callers as `local`.** The audit now takes
   the caller identity from the request. Lint test: `TestToolAuditsUseCaller`.
4. **Start-up error missing from the journal** (busy port): the process ended
   before the log copy reached stderr. `die()` now flushes the log first.
5. **`install-remote.sh` printed commas** in the firewall loop (`IFS=,`).
6. **`doctor --remote` listen probe** left "TLS handshake error … EOF" in
   the server log. The probe now does a real TLS handshake.
7. **`tls selfsign --renew`** printed a false "no --grant" warning.
8. **Docs:** `remote.md` said a cert renew changes no client. Clients that
   trust the cert file (not the pin) need the new `tls.crt`.
9. **`fb_config_get` / `fb_config_set` on Linux** looked for
   `<bin_dir>/firebird.conf`, but Linux keeps it one folder up
   (`/opt/fb50/firebird.conf`). `configedit.ConfPath` now uses the folder
   above `bin_dir` when `bin_dir` is a `bin` folder without the file.
10. **`install-remote.sh` wrote `instances: []`**, and the kernel refuses an
    empty list, so the first start failed (L2). The script now writes
    instance `fb1` from the Firebird unit (`ExecStart` path, port from
    `firebird.conf`).
11. **`fbmcpctl approve <id>` for an expired id** printed
    `no pending actions` with exit 0, and the operator took it for an
    approval (it happened twice). It now prints `no such pending action …
    expires after 15m0s` and exits 1. Test: `TestApproveUnknownIDFails`.
12. **`fbmcpctl setup --write-posture`** printed old text (a dev config
    name, the env-only secret rule). It now prints the real secret lookup
    order and warns only for databases that read as SYSDBA.
13. **`tls selfsign --grant "NT SERVICE\<name>"` failed before the service
    existed** (W): icacls cannot map the SID (error 1332), but the runbook
    makes the key first. The key ACL is now set through the Windows API with
    the computed service SID. Test: `TestGrantKeyReadUnknownService`.
14. **The tray ignored Tier-1 requests of an autonomous identity.** It
    showed Tier ≥ 2 only, so an out-of-band-only request had no Windows
    approver. It now shows every request that needs an operator. Test:
    `TestNeedsOperator`; W: the `wauto` backup showed and ran.
15. **Security: `C:\fbmcp` inherited Modify for Authenticated Users** (a
    new folder under `C:\`). Any local user could replace `fbmcp.exe` or the
    config. `install-remote.ps1` now sets a protected ACL (SYSTEM and
    Administrators full, Users and the service account read) when the folder
    holds only fbmcp files; `install-service.ps1` prints a warning. The
    "cannot write" message is now OS-neutral.
16. **`fb_service_restart` on Windows left Firebird stopped** (W, T4).
    `sc stop` returns at once; the start came during STOP_PENDING, failed
    with 1056, and the service then stopped. Stop, start and restart now
    wait for the final state, with one 1056 retry, and the result names it
    (`restarted (STOPPED, then RUNNING)`). Test:
    `TestServiceRestartWaitsForStopped`.
17. **`fb_config_set` refused `40K`** although `fb_config_get` shows it and
    Firebird reads k/m/g suffixes. Test: `TestValidateIntSuffix`.
18. **`fb_config_set` rewrote every line of `firebird.conf`**: inline
    comments, indentation and CRLF were lost, and `;` was taken as a comment,
    so list values such as `TempDirectories = c:\a;d:\b` were cut (also in
    `fb_config_get`). Now only the changed line is rewritten; a same-value set
    on the 1228-line HQbird file is byte-identical. Test:
    `TestApplyKeepsOtherLines`.
19. **`fb_agent_config_set` wrote the candidate before it checked the token.**
    With a wrong token the reload got 401 and the result said "live config
    unchanged", but the agent promotes a pending candidate by itself. It now
    checks the agent first and writes nothing on failure; a failed reload
    that is not a refusal says the candidate is still pending. Tests:
    `TestAgentConfigSetBadTokenWritesNothing`, `TestAgentRefused`.
20. **`doctor --remote` on Windows** did not find a service with another name
    (`-Name fbmcpw`) and gave FAIL for a missing `-serve`, though a Windows
    service serves without it (F4, confirmed in W). It now finds the service
    whose command names the config and gives a WARN. `apikey rotate` / `list`
    use the same lookup for the service-environment check.

## Open items (not fixed in phase 12)

- **401 / 403 are not audited.** Only the `allow_from` denial writes
  `auth.denied`. A wrong key or a bad Origin leaves no audit line.
- **A gate DENIED answer has `isError=false`.** Clients cannot see the
  refusal from the flag.
- **`fb_config_set` checks the parameter only after approval** (older code,
  ADR-020 registry). The operator can approve a request that cannot work
  (lab: `ConnectionTimeout` is not in the registry).
- **`fb_service_restart` on Linux reports success with an empty message**
  (`systemctl` prints nothing; Windows now names the final state).
- **Duplicate keys in `firebird.conf`:** `fb_config_get` reads the last
  occurrence, `fb_config_set` changes the first.
- **One tray per host:** the tray is single-instance, so a host with two
  fbmcp installs (W: the dev kernel and the service) needs a tray swap.
- **`fb_db_register` needs the instance `default_*` fields** even when the
  call gives all overrides (older design).
- **`RegisterDatabase` / `RegisterAgent` rewrite `fbmcp.yaml`** with
  `yaml.Marshal`, so comments are lost (older code).
- **`fb_agent_discover` on Linux** cannot read the agent journal as the
  `firebird` user; the result says so.
- **No Linux fbagent installer.** The L2 VM runs without fbagent, so T5 ran
  on clawnuc3 only.
- **The 15-minute request limit is fixed** (`gate.DefaultTTL`). For a
  Linux operator without the tray it was short: two pairs of requests
  expired before `approve`. A config setting or a webhook reminder may help.

## Security observations (files not read)

Windows workstation (HQbird installer, upstream report):

- `C:\HQbird\Firebird30` gives **Modify to Authenticated Users** (inherited
  from `C:\`), and `firebird.exe` of FB3 runs as **LocalSystem**. Any local
  user can replace the engine or its plugins and run code as SYSTEM, and can
  change `firebird.conf`. Operator fix: remove the inheritance and give
  Users read only. fbmcp had the same problem in its own folder (bug 15).
- The same inherited Modify is on almost every folder under `C:\Hqbird`
  (Firebird25/30/40/50, conf, Mon, AMV3, ...), and on the agent folders
  `fbagent-p3053`, `-p3054`, `-p3065` (not on `-p3055`, `-p3056`,
  `Firebird505`). The agent services run as **LocalSystem**. The live
  `agent_config.json` is locked, but any local user can create files in the
  folder, for example an `agent_config_pending_<UTC>.json` candidate, which
  the agent promotes on its next config tick (ADR-037 path). Not tested.
  Same operator fix; the installer should set a protected ACL.

clawnuc3:

- `/opt/hqbird-fbagent/agent_config_applied_20260921_123227.json` is mode
  0644. It is a full config copy, so it can carry the agent token (same as
  upstream finding F1 in `fbagent-upstream-findings.md`). The copies the
  agent made today are 0600, so the newer agent writes them correctly; the
  old file needs `chmod 600`.
- `/root/agent_config.json.pre-unit-fix` is mode 0644 and `/root` is 0755,
  so any local user can read it. Operator action: `chmod 600` or delete it.
